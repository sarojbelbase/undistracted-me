WHAT IT IS
----------
Undistracted Me replaces the new tab with a calm, distraction-free dashboard:
a Nepali (Bikram Sambat) calendar alongside the Gregorian date, a Focus Mode
with a full-screen cinematic clock and optional rain sounds, and a grid of
30+ optional, drag-and-drop widgets (notes, expenses, countdowns, NEPSE
stocks, weather, Pomodoro, media controls, RSS news, and more). No account,
no ads, no tracking — data stays on the device. Works offline. Open source (MIT).


NO OBFUSCATION / NO SHARED CLIENT SECRET
----------------------------------------
The bundle contains no obfuscated code and no shared secrets. The only
client-side identifiers are public OAuth client IDs (Google PKCE "Web
application" client, Spotify PKCE client), emitted as plain constants — they
are public by design and require no encoding.

All Google OAuth is PKCE with a server-side token exchange; the client_secret
lives only in the backend environment and never ships in the bundle. Backend
endpoints are access-gated by Origin allow-listing (see below), and the Google
token endpoint additionally validates redirect_uri against a server-side
allowlist + PKCE code_verifier, so there is no shared key to leak or rotate.


OAUTH FLOWS
-----------
1. Google (all browsers)
   PKCE via chrome.identity.launchWebAuthFlow. Authorization code exchanged
   server-side through our backend endpoint:
     https://api.undistracted.me/auth/google/token

   Bundle contains: VITE_GOOGLE_CLIENT_ID (public PKCE client, plaintext)
   Server holds: GOOGLE_CLIENT_SECRET (environment variable only)
   The endpoint validates redirect_uri (allowlist + extension-ID pattern) and
   exchanges code + code_verifier. Single-use code; never calls Google with a
   stored secret on the client.
   Source: src/utilities/googleAuth.js, functions/auth/google/token.js

2. Spotify
   PKCE via launchWebAuthFlow. Only client_id + locally-generated
   code_verifier are sent; token exchange goes directly to Spotify, never
   through our servers. Tokens stored in chrome.storage.local (never
   localStorage). Source: src/widgets/media/


PERMISSIONS & PURPOSE
---------------------
  identity              → Google OAuth (PKCE) + Spotify OAuth
  storage               → Widget settings, OAuth tokens (chrome.storage.local for sensitive)
  geolocation           → Weather widget (browser prompts user before any read)
  topSites              → Quick Access widget (displayed inline only)
  notifications         → Event reminders, Pomodoro, look-away breaks
  alarms                → Periodic tasks (event checks, timers, RSS prefetch)
  idle                  → LookAway OS idle/locked-state cross-check (bg.js)
  tabs                  → Media-controls relay: the extension queries open tabs
                          to find which one has an active media session so play/
                          pause/next route to the right tab, and to inject the
                          media content script into already-open YouTube/
                          SoundCloud tabs. URLs/titles are only read for this
                          routing; no browsing history is collected or stored.
  scripting             → Inject media.js into already-open YouTube/SoundCloud tabs
  declarativeNetRequest → Website Blocker: dynamic rules to block distracting
                          domains (Focus Mode); IDs 1000+, user-configured only
                          Source: src/utilities/siteBlocker.js

HOST PERMISSIONS
----------------
Scoped to exactly the origins the extension actually contacts (YouTube/SoundCloud
media, Spotify, Google APIs, weather/geolocation, stocks, search-suggest, jokes,
and the undistracted.me API). No broad `<all_urls>` / `*://*/*` grant is present.


CONTENT SCRIPTS
---------------
  Sites: YouTube, SoundCloud (media.js), run_at document_idle
  Purpose: Poll mediaSession, route MEDIA_ACTION commands [play, pause, next, previous]
  Validation: All messages validated against an explicit allowlist
  No: innerHTML, eval, or external data exfiltration

WEB-ACCESSIBLE RESOURCES
------------------------
  entries/blocked.html (+ assets/blocked*) exposed on <all_urls> for the
  "site blocked" interstitial shown by Focus Mode. This is required so the DNR
  redirect can load the block page from any blocked site; it is a static,
  non-privileged page that exposes no extension internals. A website could
  probe the pinned extension ID to detect installation (accepted tradeoff —
  no data is exfiltrated; the iframe is cross-origin isolated). The page's
  `?d=` parameter is validated against a strict hostname regex before any use.
