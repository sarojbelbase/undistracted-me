Part I — Privacy Policy
Section 1

What We Collect

Undistracted Me is designed to keep your data on your device.

The short version

We do not operate a user database. We do not collect your name, email, or any personally identifiable information on our own servers. We do not track your browsing history. All widget configuration stays in your browser's local storage.

Data that stays on your device

  • Widget layout, sizes, and positions.
  • Widget-specific settings (clock timezones, weather city, stock tickers, etc.).
  • Focus Mode preferences (background choice, enabled widgets, panel settings).
  • Nepali calendar preferences and display language.
  • Any notes you write in the Notes widget.
  • Pomodoro and timer history.

Cross-device sync (optional)

If you choose to enable cross-device sync, a copy of your settings, widget layout, events, bookmarks, countdown timers, and notes is stored in a hidden app-data folder in your Google Drive, tied to your Google account. This is fully optional and enabled only when you sign in with Google. The folder is invisible in your normal Drive view and accessible only to the extension. No synced data is sent to or stored on our servers — the extension writes directly to Google Drive’s API using a token scoped to drive.appdata access only.

Data passed through our backend

Some API calls are routed through our backend at api.undistracted.me so that secret API keys are never embedded in the extension bundle. These calls are:

  • Unsplash photos — a random background photo is fetched. No personal data is sent. The response is a photo URL.
  • Google token exchange (Firefox only) — the OAuth authorisation code is exchanged for tokens server-side so the client_secret never leaves our server. The token is returned to your browser immediately and not stored by us.
  • Favicon proxy — a website domain name is sent to fetch its icon. No session or identity data is included.

Our backend does not log user-identifiable information. Standard web-server access logs (IP address, timestamp, HTTP method) may be retained for up to 30 days by our hosting provider (Cloudflare) for security and abuse-prevention purposes.

Geolocation

The Weather widget can optionally use your location to show local weather. The browser prompts you for permission before any coordinates are read. Coordinates are sent directly to Open-Meteo (a privacy-respecting, open-source weather service) and are never stored or sent to us. If you decline, you can enter a city name manually.

As a last resort when neither browser geolocation nor a manual city is available, the extension may call a public IP-based geolocation service (freeipapi.com for extension origins; ipapi.co additionally when the extension runs as a website). The undistracted.me website itself contacts freeipapi.com to detect your country for currency-localized pricing. Only your IP address is sent; no personal identifier is stored. Both domains are declared in the extension’s host_permissions and are only contacted for this fallback purpose.

Note on OAuth tokens

When you connect Google or Spotify, an OAuth access token is issued by the respective service and stored in your browser's local storage (or session storage in website mode). This token is sent with each API call to authenticate you — it is never sent to our servers except during the Firefox Google token exchange, where it is forwarded immediately to your browser without being persisted. The Google token is scoped to Calendar, Contacts, Tasks, and drive.appdata (cross-device sync) access only.

Section 3

Google Integration

Undistracted Me can optionally connect to your Google account. No Google feature is active until you explicitly sign in.

Permissions requested

Scope Used by Access level
userinfo.profile Display your name and avatar Read only
userinfo.email Identify which account is connected Read only
calendar.readonly Google Calendar widget — upcoming events Read only
contacts.readonly Contact search in the events panel Read only
tasks Tasks panel — view, create, complete, delete tasks Read & Write
drive.appdata Cross-device sync — store config & notes in a hidden Drive app-data folder Read & Write (own app data only)

What we do with Google Tasks

  • Read tasks from all of your task lists (up to 100 tasks per list, including completed).
  • Create new tasks in your default task list.
  • Update a task's title when you double-click to edit it (in its specific list).
  • Mark a task completed or un-completed via the checkbox.
  • Permanently delete a task when you click the trash icon.

What we do NOT do

  • Read task notes, sub-tasks, or due dates beyond what the API returns.
  • Sync, cache, or transmit your task data to any server — it exists only in React memory while the tab is open.

Data Protection for Sensitive Data

We protect your sensitive Google user data (Calendar events, Contacts, and Tasks) by ensuring it never leaves your device. We do not operate any database or remote storage servers. Your data is securely stored purely locally on your device within your browser's sandboxed chrome.storage.local or localStorage environment, which is accessible only by the extension itself. We employ encryption in transit (HTTPS) for all direct API calls between your browser and Google's servers.

Data Retention and Deletion

We retain your Google user data locally only for as long as your account remains connected to the extension. We provide an explicit "Disconnect" mechanism in the extension's Account Settings panel. The moment you click Disconnect, all cached Google user data, profile information, and authentication tokens are immediately and permanently deleted from your local storage. Furthermore, uninstalling the extension prompts the browser to automatically delete all associated local storage data.

Revoking access

In addition to disconnecting within the extension, you can revoke the extension's permissions entirely at any time from myaccount.google.com/permissions. Revoking access does not delete any data from Google's servers — it only removes our application's ability to read or interact with your Google data.

Google authentication flow

Google sign-in uses a single OAuth 2.0 "Web application" client with the PKCE authorization-code flow on every browser (Chrome, Brave, Edge, Opera, Vivaldi, and Firefox). The authorization code is exchanged for tokens via our backend endpoint, which injects the client_secret server-side. The secret is never present in the extension bundle — only the public client_id is.

Section 4

Spotify Integration

The Spotify widget is entirely opt-in and requires explicit sign-in.

Spotify authentication uses the standard PKCE flow. Only the client_id and a locally-generated code_verifier are sent — no client secret is involved. Token exchange goes directly to accounts.spotify.com/api/token and never through our servers.

  • Tokens are stored in chrome.storage.local (extension) or sessionStorage (website mode — cleared when the tab is closed).
  • Your Spotify display name and account tier (Free/Premium) are persisted in localStorage so they display on return visits. Your avatar URL is not persisted — it is held in memory for the current session only and re-fetched on reconnect.
  • The extension reads your currently playing track and controls playback (play, pause, next, previous, seek).
  • No listening history or personal data is collected by us.

Browser media sessions (SoundCloud & others)

A content script is injected into SoundCloud pages (*://*.soundcloud.com/*) only. It polls navigator.mediaSession for track metadata and sends it to the background service worker so it can be displayed in the Focus Mode media panel. No data is sent to any external server. The content script does not modify the SoundCloud page.

Section 5

Google Drive Sync

Optional cross-device sync through your Google Drive. Enabled when you sign in with Google.

How it works

Cross-device sync stores a copy of your settings, widget layout, events, bookmarks, and countdown timers in a single hidden app-data folder inside your own Google Drive. Your notes are stored separately — each note is its own file in that same hidden folder, with only a small index (note id and title) kept in the config file. This folder is invisible in your normal Drive view and accessible only to the extension. The extension reads and writes these files directly through Google Drive’s API — your data never passes through our servers.

Authentication & permissions

  • You sign in with your Google account — the same sign-in used for Calendar, Contacts, and Tasks.
  • We request a single additional scope: drive.appdata. This lets the extension create, read, and update files in its own hidden app-data folder, and nothing else — it cannot see any other files in your Drive.
  • The access token is stored in chrome.storage.local (the same sandbox used for Google and Spotify tokens).

What is stored

Data Stored in Drive?
Settings, theme, accentYes
Widget layout & per-widget settingsYes
Events (native), bookmarks, countdownYes
NotesYes
Google Calendar / Spotify tokensNever
Weather cache, photos, RSS items, locationNever

Sync schedule

Sync is not continuous. The extension syncs automatically once a day, and you can trigger an immediate sync at any time from Settings → Data. A 5-minute throttle prevents rapid or repeated syncing.

Retention & deletion

  • Disconnect (Settings → Accounts) immediately deletes the stored token from your device and stops syncing.
  • The synced files live in a hidden app-data folder in your Google Drive, accessible only to the extension. You can revoke the extension’s access entirely from myaccount.google.com/permissions.
Section 6

Data Storage

All user data is stored locally in your browser.

Storage type What is stored When cleared
chrome.storage.local Widget settings, Spotify tokens, Google Calendar cache, OAuth connected flags Extension uninstall
localStorage UI preferences, theme, widget layout, search history, Zustand state Manual clear / uninstall
sessionStorage (website only) Google and Spotify OAuth tokens — scoped to tab session Tab close
Google Drive app-data folder (optional) Settings, widget layout, events, bookmarks, countdown, notes — only if you sign in with Google Hidden from your Drive; revoke access to stop

Security Measures

  • Storage Isolation: Sensitive data (like Google events and contacts) is sandboxed in chrome.storage.local, which cannot be accessed by other websites. Less sensitive UI preferences use standard localStorage.
  • Web Mode Security: When using the web version, OAuth tokens are strictly stored in sessionStorage, guaranteeing they are permanently wiped from your browser the moment you close the tab.
  • Minimal Persistence: Only non-identifying data (display name, account tier) is persisted in localStorage. User-identifying artefacts such as avatar URLs are held in memory only and never written to persistent storage.
  • Server-Side redirect_uri Validation: The Google token-exchange endpoint validates redirect_uri against a server-side allowlist, preventing stolen authorisation codes from being exchanged via a forged redirect.
  • API Key Obfuscation: We employ build-time cryptographic obfuscation for internal API keys (like the Google OAuth client ID) to prevent automated scrapers from extracting them from the codebase.

No data is synced to the cloud via chrome.storage.sync. Data does not leave your device except for the API calls described in Section 2 and, if you enable cross-device sync, the copy stored in your Google Drive app-data folder (Section 5).
